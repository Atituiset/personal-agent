# 核心信念

这些信念决定了仓库怎么组织。来源：本项目的设计原则（[../design.md](../design.md) 第 0 节）和 OpenAI《Harness engineering》一文里的做法。

1. **仓库是唯一的事实来源。** 智能体看不到聊天记录、口头约定和别人脑子里的背景。决定、计划、例外都要落到仓库里
   （执行计划见 [../../PLANS.md](../../PLANS.md)，例外见 [../exec-plans/tech-debt-tracker.md](../exec-plans/tech-debt-tracker.md)）。
2. **AGENTS.md 是目录，不是百科。** 它只告诉你去哪看；细节放在 `docs/` 下对应的文档里，由文档检查保证链接不断、内容不过期。
3. **能机械检查的规则不靠提醒。** 分层、文档新鲜度、黄金原则都有脚本检查，报错信息里直接写怎么修。
4. **系统自己说了算，智能体的自述不算。** 评测只看数据库、产物和调用账本里真实发生的事（[../../evals/README.md](../../evals/README.md)）。
5. **失败不冒充成功。** 超时、预算耗尽、等待审批都是明确的状态；不能吞掉异常当作成功。
6. **反馈回路要短。** 本地一条命令能起隔离实例、查日志和指标、跑预算检查；门禁失败时直接给出下一步该看什么。
7. **对外副作用默认要人工确认。** 发邮件、发帖、推代码这类动作不在无人值守的路径上自动执行。
